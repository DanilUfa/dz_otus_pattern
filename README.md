## Иерархия классов

Четыре конкретных класса образуют три последовательных уровня наследования:

| Класс | Родитель | Назначение и собственные данные |
| --- | --- | --- |
| Document | — | Документ: заголовок и список тегов |
| Report | Document | Отчёт: автор и список разделов |
| FinancialReport | Report | Финансовый отчёт: валюта и словарь денежных показателей |
| AnnualFinancialReport | FinancialReport | Годовой финансовый отчёт: год и замечания аудитора |

Каждый класс можно создать и клонировать отдельно.

## Реализация Prototype

`IMyCloneable<out T>` объявляет типизированный метод `T Clone()`.
Публичный виртуальный `Clone()` переопределён в потомках с ковариантным
возвращаемым типом. Поэтому вызов даже через ссылку Document сохраняет
фактический тип AnnualFinancialReport и все его данные.

Каждый класс имеет конструктор копирования. Конструктор потомка вызывает
`base(source)`, а затем копирует собственные поля. Ни сериализация, ни
MemberwiseClone не используются.

Принята семантика **глубокой копии**: все списки и словарь создаются заново.
Их элементы — неизменяемые строки или значения decimal, поэтому отдельного
клонирования элементов не требуется. Изменения оригинала или копии не
влияют на другие экземпляры. Циклические графы объектов здесь не моделируются.

Стандартный `System.ICloneable` реализован явно в Document и наследуется
всеми потомками. Его единственный метод делегирует работу виртуальному
`Clone()`, поэтому алгоритм не дублируется. Потомки дополнительно реализуют
`IMyCloneable<СвойТип>` явно, делегируя вызов тому же методу.

Пример:

```csharp
var source = new AnnualFinancialReport("Отчёт", "Данил", "RUB", 2026);
source.Amounts.Add("Выручка", 100m);

IMyCloneable<AnnualFinancialReport> prototype = source;
AnnualFinancialReport copy = prototype.Clone();
copy.Amounts["Выручка"] = 200m; // source по-прежнему содержит 100m

ICloneable standard = source;
var anotherCopy = (AnnualFinancialReport)standard.Clone();
```

## Запуск

Нужен .NET SDK 9.0. Внешние NuGet-пакеты не требуются.

```powershell
dotnet build PrototypePattern.sln --configuration Release
dotnet run --project demo/PrototypePattern.Demo --configuration Release
dotnet run --project tests/PrototypePattern.Tests --configuration Release
```

Demo печатает оригинал, изменённую типизированную копию и копию через
ICloneable. Оригинал и вторая копия сохраняют исходные значения.

Tests — самостоятельная консольная программа проверок, **запускается через
dotnet run**, а не dotnet test. При любой неудачной проверке возвращает код 1.
Проверяет оба интерфейса у всех четырёх классов, сохранение полей и типа,
отсутствие общих коллекций, типизированные интерфейсы на каждом уровне,
вызовы через базовые ссылки и независимость двух копий от оригинала и друг друга.
Ожидаемый результат: `7/7 checks passed.`

## Сравнение интерфейсов и вывод

| Критерий | IMyCloneable<T> | System.ICloneable |
| --- | --- | --- |
| Тип результата | T, приведение не требуется | object, обычно нужно приведение |
| Проверка типов | Тип результата известен компилятору | Ошибочное приведение может проявиться во время выполнения |
| Совместимость | Собственный контракт, потребитель должен знать о нём | Стандартный интерфейс .NET |
| Иерархия | Ковариантность out позволяет использовать интерфейс базового типа; для точного типа потомка нужны дополнительные реализации | Одна унаследованная реализация с виртуальным вызовом обслуживает всю иерархию |
| Семантика копии | Мы явно задали глубокое копирование в документации контракта | Сам интерфейс не определяет, должна ли копия быть глубокой или поверхностной |

IMyCloneable<T> удобнее в прикладном коде: сохраняет типобезопасность,
убирает приведения и позволяет явно описать договор о копировании.
Его недостатки — собственный нестандартный API и дополнительный код для
типизированного клонирования в иерархии.

ICloneable полезен при взаимодействии с кодом, который уже ожидает этот
стандартный интерфейс. Его недостатки — результат object и неопределённая
глубина копирования на уровне самого интерфейса. В данном решении оба
интерфейса используют один алгоритм и дают одинаковые глубокие копии.
