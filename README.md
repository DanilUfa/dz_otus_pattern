# PrototypePattern — паттерн «Прототип»

Домашнее задание: иерархия классов с клонированием по паттерну «Прототип»
(свой интерфейс `IMyCloneable<T>` и стандартный `ICloneable`).

## Предметная область и описание классов

Иерархия **транспортных средств** (две ветви наследования):

```
Transport (база)
 ├── Car
 │    └── ElectricCar
 └── Bicycle
```

| Класс | Описание |
|---|---|
| `Transport` | Базовый класс: название, максимальная скорость, список доп. опций (`List<string>` — ссылочное поле, копируется глубоко) |
| `Car` | Наследник `Transport`: добавляет число дверей и тип топлива |
| `ElectricCar` | Наследник `Car`: добавляет ёмкость батареи (второй уровень наследования) |
| `Bicycle` | Наследник `Transport`: добавляет признак наличия корзины (отдельная ветка иерархии) |

Каждый класс имеет:
- обычный конструктор;
- **copy-конструктор** (protected, вызывает родительский copy-конструктор — цепочка от потомка до базы);
- метод `Clone()` с ковариантным возвращаемым типом, реализующий `IMyCloneable<T>`;
- явную реализацию `object ICloneable.Clone() => Clone()`, делегирующую своему методу.

## Запуск

```
dotnet run -c Release
```

Программа создаёт оригиналы, клонирует их и прогоняет автоматические проверки
(тип клона, независимость ссылок, полнота копии, глубокая копия списка опций,
ковариантность `IMyCloneable<out T>`, работа `ICloneable`).

## Вывод: преимущества и недостатки интерфейсов

### `IMyCloneable<T>` (пользовательский)

**Преимущества:**
- возвращает **типизированную** копию — не нужны приведение и проверка типа при использовании;
- ковариантность `out T`: `IMyCloneable<ElectricCar>` можно использовать как `IMyCloneable<Transport>`;
- семантика явно задана нами: «клонирование = полная (глубокая) копия», поведение одинаковое во всей иерархии.

**Недостатки:**
- это **нестандартный** интерфейс: работает только в нашем коде, сторонние/библиотечные компоненты о нём не знают;
- за каждым новым типом нужно «тащить» свой `IMyCloneable<T>` (общий, не-дженерик вариант теряет типизацию).

### `ICloneable` (стандартный, .NET)

**Преимущества:**
- **встроенный** интерфейс платформы: его понимает любой .NET-код, он не требует дополнительных определений;
- один раз описан — применим к любому типу, легко передавать клоны через базовые типы.

**Недостатки:**
- метод `Clone()` возвращает `object` — каждый вызов требует **приведения типа** (риск `InvalidCastException`, ошибки только в рантайме);
- контракт **не задаёт глубину** копии: одна реализация делает поверхностную копию, другая глубокую — поведение непредсказуемо для вызывающего кода;
- из-за этих проблем `ICloneable` считается слабым местом .NET (его не рекомендуют использовать в новых API).

### Итог

`IMyCloneable<T>` удобнее и безопаснее внутри проекта: типизированный возврат
и единая конвенция глубокого клонирования. `ICloneable` нужен для совместимости
со стандартным кодом. Поэтому оба интерфейса реализованы в каждом классе:
`ICloneable` просто делегирует своей `Clone()` — один механизм, две «точки входа».
