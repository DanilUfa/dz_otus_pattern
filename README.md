# Прототип

ДЗ по паттерну «Прототип». Для примера взял транспорт.

Сделал 4 класса с наследованием:

- `Vehicle` — транспорт, есть название и список дополнительных опций.
- `MotorVehicle` наследуется от `Vehicle`, добавляет мощность двигателя.
- `Car` наследуется от `MotorVehicle`, добавляет количество мест.
- `ElectricCar` наследуется от `Car`, добавляет ёмкость батареи.

Каждый из этих классов можно создать и клонировать отдельно.

## Как сделал клонирование

Добавил свой интерфейс `IMyCloneable<T>` с методом `Clone()`. У каждого класса метод возвращает копию своего типа.

Для копирования использовал конструкторы. Потомок вызывает `base(source)`, чтобы скопировать родительские поля, а потом копирует свои. Метод `Clone()` виртуальный, поэтому даже через переменную типа `Vehicle` электромобиль копируется как `ElectricCar`, со всеми его полями.

Список опций тоже создаётся заново. Если добавить опцию в копию, у оригинала она не появится. В списке строки, они неизменяемые, поэтому отдельно копировать каждый элемент не нужно.

Стандартный `ICloneable` реализовал в `Vehicle`. Остальные классы его наследуют. Он вызывает тот же `Clone()`, то есть второй вариант копирования писать не пришлось.

Пример вызова через оба интерфейса:

```csharp
var original = new ElectricCar("Электромобиль", 200, 5, 75);
original.Accessories.Add("Камера");

IMyCloneable<ElectricCar> prototype = original;
ElectricCar copy = prototype.Clone();
copy.Accessories.Add("Навигатор");

var anotherCopy = (ElectricCar)((ICloneable)original).Clone();
```

## Запуск и проверка

Нужен .NET SDK 9.0. Из папки проекта:

```sh
dotnet run -c Release
```

В консоли сначала выводится пример с оригиналом и копиями, потом идут проверки. Проверил оба интерфейса для всех классов, копирование полей, сохранение типа при вызове через родителя и независимость списков у оригинала и двух копий.

Проверки находятся в `Program.cs`, отдельный тестовый проект не делал. Запускаются вместе с программой. В конце должно быть `Пройдено: 7/7`. Если проверка падает, программа выводит ошибку и завершается с кодом 1.

## Вывод по интерфейсам

Мне удобнее `IMyCloneable<T>`, потому что сразу получаю нужный тип, например `ElectricCar`, без приведения из `object`. Ошибку с типом можно увидеть при компиляции. Минус — это свой интерфейс, его надо добавлять в проект и реализовывать для типов потомков. Сам по себе дженерик не делает копию глубокой: за это всё равно отвечает код копирования.

Плюс `ICloneable` в том, что он уже есть в .NET и подходит для кода, который ожидает именно этот интерфейс. В моей иерархии хватило одной реализации в базовом классе. Минусы — возвращает `object`, поэтому нужно приведение, и из самого интерфейса непонятно, будет копия глубокой или поверхностной.

В этом примере оба интерфейса создают независимые копии. Для своего кода я бы выбрал `IMyCloneable<T>`, а `ICloneable` оставил бы там, где он требуется.
