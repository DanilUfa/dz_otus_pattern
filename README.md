## Описание классов

Цепочка наследования: `Vehicle` → `MotorVehicle` → `Car` → `ElectricCar`.
Каждый из четырёх классов можно создать и клонировать отдельно.

| Класс | Родитель | Собственные данные |
| --- | --- | --- |
| Vehicle | — | Название, изменяемый список дополнительных опций |
| MotorVehicle | Vehicle | Мощность двигателя в лошадиных силах |
| Car | MotorVehicle | Количество мест |
| ElectricCar | Car | Ёмкость батареи в кВт·ч |

## Реализация

`IMyCloneable<out T>` содержит метод `T Clone()`. Каждый класс реализует
интерфейс со своим типом результата. Виртуальный метод переопределяется
с ковариантным возвращаемым типом: клонирование электромобиля через ссылку
`Vehicle` также создаёт `ElectricCar` и сохраняет поля всех уровней.

Клон создаётся конструктором копирования. Каждый конструктор потомка
вызывает `base(source)`, затем копирует собственные данные. Список опций
создаётся заново. Его элементы — неизменяемые строки, поэтому копирование
данной модели глубокое: изменения списка клона не влияют на оригинал.

`ICloneable` реализован явно в `Vehicle` и наследуется всеми потомками.
Его метод вызывает виртуальный `Clone()`, используя тот же алгоритм.

```csharp
var source = new ElectricCar("Электромобиль", 200, 5, 75);
source.Accessories.Add("Камера");
IMyCloneable<ElectricCar> prototype = source;
ElectricCar copy = prototype.Clone();
copy.Accessories.Add("Навигатор"); // Оригинал не изменился.
var standardCopy = (ElectricCar)((ICloneable)source).Clone();
```

## Запуск

Нужен .NET SDK 9.0. Внешние NuGet-пакеты не используются.

```cmd
dotnet build -c Release
dotnet run -c Release
```

Программа показывает оригинал и копии через оба интерфейса, затем выполняет
семь групп проверок: оба интерфейса у четырёх классов, типизированные результаты,
полиморфизм и ковариантность, независимость оригинала и двух копий.
Проверяются поля всех уровней, фактический тип и отсутствие общего списка.
Ожидаемый результат: `Пройдено: 7/7`. При ошибке код завершения равен 1.
Это консольные проверки, запускаемые через `dotnet run`, а не `dotnet test`.

## Сравнение интерфейсов и вывод

| Критерий | IMyCloneable<T> | ICloneable |
| --- | --- | --- |
| Результат | Тип T, приведение не нужно | object, для доступа к свойствам конкретного класса требуется приведение |
| Типобезопасность | Тип результата проверяет компилятор | Ошибка приведения возможна во время выполнения |
| Совместимость | Собственный интерфейс проекта | Стандартный интерфейс .NET |
| Глубина копирования | В нашем контракте явно обещана глубокая копия | Стандартный контракт не определяет глубину копирования |
| Наследование | Для точного результата нужны реализации интерфейса потомков; out поддерживает ковариантность | Базовая реализация обслуживает всю иерархию через виртуальный вызов |

`IMyCloneable<T>` удобен для прикладного кода: сохраняет тип результата,
убирает приведения и позволяет явно определить семантику копирования.
Недостатки — нестандартный контракт и дополнительный код в иерархии.

`ICloneable` подходит для совместимости с потребителями стандартного интерфейса.
Его недостатки — результат object и отсутствие гарантии глубокой копии
на уровне интерфейса. В этом решении оба интерфейса вызывают одни
конструкторы копирования и создают одинаково независимые объекты.
